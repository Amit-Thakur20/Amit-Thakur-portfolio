Case Study 01

Finote: an RBAC-driven ERP for Architect and construction firms

I designed and shipped Finote from scratch — an RBAC-driven ERP that replaced fragmented spreadsheets, files, and mail threads with a single shared record for projects, billing, certificates, drawings, site reports, and tasks. Every role — architect, finance, site engineer, client, developer — reads the same project, at the same time, with the same numbers.

The problem

Architecture and construction firms ran their operations the way the industry always had — Excel sheets for projects, scattered files for drawings, and mail threads to coordinate between the office, accounts, and the site. Each role held its own slice of truth, and the architect-owner had no single view of their own business.

The structural pain One layout → many buildings → many developers → many fee tracks. Tracking who owed what against which slab meant a separate spreadsheet per relationship.
Money lagging the build Site progress happened daily; demand letters, fee calculations, tax splits, and invoices were reconstructed weeks later by accounts re-typing numbers that already existed.

The design challenge: make money a consequence of operations — not a separate workflow that has to be reconciled.

How we knew we solved it

Four signals I used to declare victory:

  • Activation gate A project cannot go live until fees are added. Finance is the source of truth on day one; no project drifts into setup limbo while accounts catches up.
  • One record, five views Admin, site engineer, accounts, client, and developer each log in and see only what is relevant to them — against the same underlying record.
  • Money tracks the build, automatically Site progress + fee chart routes to a demand letter. Payment + tax split routes to an invoice. No manual re-entry anywhere in the chain.
  • Approval-driven edits When any employee edits a record, it doesn't go live — it raises a request on the admin's dashboard. Admin approves or rejects before the record updates. Trust without lockdown.

What I did

01

Discovery across firms

Shadowed architects, accounts, and site engineers to map who touches what — and where the records broke.

02

Domain modeling

Designed the layout → building → wing hierarchy so one project could honestly hold many developers on the same piece of land.

03

RBAC by design

Built the role matrix around real jobs-to-be-done: admin, site engineer, accounts, client, developer.

04

Approval workflow as a first-class feature

Every employee edit becomes a request; only admins can approve. Everyone sees proposed changes before they go live.

05

Operational dashboard

Scoped the home screen around KPIs each role cares about; live activity stream is the notification layer.

06

Lifecycle wiring

Connected site report → demand → payment log → invoice so finance never re-typed what the field team already wrote.

What I shipped

1. Role-aware operations dashboard

One home for every role. KPI tiles are scoped to what the signed-in user cares about; the live activity stream surfaces approvals, overdue fees, and pending site visits without leaving the page. Every notification is actionable — an edit request is one click from approval or rejection.

2. Clients, applicants, developers, groups — one directory

A single directory holds everyone the firm bills or builds for. Adding a developer here is what makes them mappable to a specific building inside a specific layout.

3. Projects with layout → building hierarchy

One project holds many buildings; many buildings can hold many developers. The list view filters by Job No., VP No., Village, Phase; the layout summary collapses scheme, billing company, team, and location into one decision-ready screen.

4. Bills & payments — the lifecycle of money

Calculate Fees on onboarding — the project goes live only when fees exist. Raise Demand routes the right fee to the right construction stage (slab, RCC, brickwork). Log Payment records cheque or RTGS with the tax split; the invoice is generated the same day.

5. Certificates

Filter the project, generate the certificate. One record per project keeps issuance auditable and downloadable.

6. Site reports and drawings

Site engineers upload progress per stage. Drawings and certificates sit alongside the same project record so anyone on the team — admin, client, developer — can pull the latest set without chasing the architect.

7. Task manager — accountability, not noise

Completion rate, project-level throughput, employee-level efficiency. Admins see who is overloaded; employees see their own queue; nobody has to ask where a task is stuck.

Impact

  • Replaced fragmented tracking with one RBAC system where architects, finance, site engineers, clients, and developers all read from the same record.
  • Made finance a consequence of operations — projects go live only when fees exist; demand letters raise themselves off site progress; invoices generate off payments the same day.
  • Built trust into the workflow — every edit is a request, every request is visible; admins approve, the rest of the org sees approved truth.
